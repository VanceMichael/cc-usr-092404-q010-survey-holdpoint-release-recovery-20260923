# 停检点测量放行规则

古廊桥分段顶升交叉作业现场，监理站依据一块放行看板判断：哪个停检点可以施工、
阻断来自测量超差还是上游工序、设计变更波及哪些班组。口头确认与散落测量批次
不作为依据；所有决定均可由证据包、缺陷、签署、租约与事件重建。

## 核心不变量

1. **原始包不可覆盖**：证据包只追加新版本（`package_version` 递增），观测摘要
   （SHA-256 + 基线标签/修订 + 仪器/校准版本）在提交时固定；任何操作不修改旧包。
2. **构件对应关系随基线版本发布**：证据包必须引用属于其声明设计版本的基线。
3. **摘要、序号、坐标完整才可仲裁**：控制点缺观测行，或序号/坐标为空，记
   `MISSING_FIELD`，不进入超差判定。
4. **测量复核人先签、监理后签**：两人双签才构成放行；任何角色都不能批准
   自己（个人账户）提交的材料。
5. **重叠工作区租约独占**：几何重叠的工作区同一时刻只允许一个在持施工租约。
6. **版本变化必须重新确认**：签署窗口内设计换版，旧包签署作废，按新版重新
   出证并重走双签。

## 工序状态机

| 状态 | 含义 |
| --- | --- |
| `PENDING_RELEASE` | 待放行（未交证、校核未过、签署未完成或放行被撤销） |
| `RELEASED` | 监理已签、尚未开工 |
| `IN_PROGRESS` | 已获施工租约，施工中 |
| `EXECUTED` | 施工完成、租约释放 |
| `AT_RISK` | 已执行工序遭遇补录/校准撤销/换版，转风险评估 |

撤销事实记录在 `release_decisions.state = CANCELLED`（原决定与原因保留），
工序本身回 `PENDING_RELEASE`。

`review_pending=1` 表示施工中遭遇补录/校准撤销/换版，挂起现场复核；未解除前
不得登记施工完成。

## 看板阻断归因（blockers）

| 阻断码 | 归因 |
| --- | --- |
| `PACKAGE_MISSING` | 承包方尚未提交证据包 |
| `MISSING_FIELD` | 控制点观测缺行，或序号/坐标不完整 |
| `OUT_OF_TOLERANCE` | 位移或沉降超过工序登记容差（主体为控制点编号） |
| `STALE_OBSERVATION` | 观测时刻早于"当前时刻 − 观测时效" |
| `CALIBRATION_REVOKED` | 证据包引用的仪器校准版本已撤销 |
| `DESIGN_CHANGED` | 证据包依据旧设计版本，须按新版重新出证 |
| `UPSTREAM_BLOCKED` | 前置工序未完成放行（详情递归给出上游原因，如"测量超差"） |
| `ADJACENT_CONFLICT` | 重叠工作区有其他工序持有在持租约 |

带有效豁免（未撤销、未到期）的阻断出现在 `waived` 而非 `blockers`。

## 缺陷、整改与豁免

- 校核把问题落地为 `findings`（码 + 控制点主体 + 证据包）。
- **整改以新证据包关闭偏差**：新包校核时，旧包开放缺陷关闭
  （`closed_by_package_id` 指向新包）；当前包已消失的问题同步关闭。
- **人工豁免**仅监理可批，必须填写依据与到期时刻；到期或撤销后阻断自动恢复。
  豁免不删除缺陷记录，已关闭缺陷不能再豁免。

## 撤销触发器（补录 / 校准撤销 / 设计换版）

| 工序当前状态 | 处置 |
| --- | --- |
| 待放行 / 已放行未开工 | 放行决定置 `CANCELLED`（保留原决定与原因），回待放行，按新情况重新出证 |
| 施工中 | 不撤销原放行，置 `review_pending`，现场复核经监理确认后解除 |
| 已执行 | 转 `AT_RISK`，保存原放行决定，开风险评估；监理结论后恢复 `EXECUTED` 台账 |

补录包必须填写补录原因；已撤销校准不能用于新证据；校准与补录记录本身保留。

## 一次设计换版的影响清单

`POST /design-changes` 返回 `changeId` 与 `affectedCrewIds`，按状态分三类：

- `REVOKE_PENDING`：待放行/未开工 → 撤销放行、重指新版；
- `IN_PROGRESS_REVIEW`：施工中 → 现场复核挂起；
- `EXECUTED_TO_RISK`：已执行 → 转风险评估并保存原决定。

`GET /design-changes/:changeId` 按三类列出停检点与班组名称。

## 批量校核的中断恢复

`review_batches` 记录游标 `cursor_index`；每个 `review_batch_items` 独立事务
提交为 `DONE`/`FAILED`。中断后再次 `advance` 从第一个 `PENDING`/`FAILED` 项
继续，已完成项不重算；全部完成后批次置 `COMPLETED`。

## 并发

- 监理签署使用条件更新（`supervisor_id IS NULL`），并发双签仅一个生效。
- 租约申请在事务内复查重叠区在持租约，争用时第二个返回 `409 LEASE_CONTENTION`。
- 证据包为版本追加写，不存在相互覆盖。

## HTTP 接口摘要

基础数据：`POST /admin/crews|users|design-versions|baselines|calibrations|work-zones|work-zone-overlaps`

方案与证据：
- `POST /steps` 登记停检点（前置工序、控制点、位移/沉降容差、观测时效）
- `POST /steps/:stepId/packages` 提交/补录证据包
- `GET  /steps/:stepId/packages` 证据包谱系
- `GET  /steps/:stepId` 停检点详情（包/缺陷/豁免/签署/风险/事件时间线）

校核与豁免：
- `POST /steps/:stepId/check`
- `POST /reviews/batches`、`POST /reviews/batches/:id/advance?limit=`、`GET /reviews/batches/:id`
- `POST /waivers`、`POST /waivers/:id/revoke`

签署与施工：
- `POST /steps/:stepId/sign`（先测量复核人、后监理）
- `POST /steps/:stepId/lease`、`POST /steps/:stepId/complete`
- `POST /steps/:stepId/site-review/resolve`

触发器与看板：
- `POST /calibrations/:id/revoke`
- `POST /design-changes`、`GET /design-changes/:id`
- `POST /risk-assessments/:id/resolve`
- `GET  /board[?zoneId=]`

错误统一为 `{ "error": "CODE", "message": "..." }`，状态码 400/403/404/409。
